# FGL-Admission: защита Hermes от environmental attack на скиллы

Дата: 2026-10-09. Задача научрука: на основе трёх статей (Dynamic Agent Skills, arXiv:2607.10113;
Agent Skill Evaluation and Evolution, arXiv:2606.11435; SkillsVote, arXiv:2605.18401) предложить
улучшение FGL для снижения риска environmental attack для Hermes.
Протокол зафиксирован до прогона: `docs/PREREG_fgl_hermes_env_attack.md`.
Код: `benchmark/fgl_hermes_env_attack.py`. Результаты: `benchmark/results/fgl_hermes_env_attack_*.json`.

## 1. Угроза

Environmental attack: атакующий не трогает ни запрос пользователя, ни файл скилла. Он кладёт
инструкцию в окружение агента (README, вывод инструмента, страница), где Hermes выполняет
безобидную задачу. Фоновый куратор Hermes продвигает подсказку из окружения в персистентный
SKILL.md, в следующей сессии скилл переиспользуется и вред активируется. Это путь
PoisonedEvolution / SkillJack (cross-layer promotion + persistence) из обзора научрука.

## 2. Что уже есть в Hermes v0.19.0 (по установленному пакету в `.venv`)

| Компонент | Что делает | Пробел |
|---|---|---|
| `agent/background_review.py`, `_SKILL_REVIEW_PROMPT` | Фоновый куратор: «Be ACTIVE ... tool-usage pattern emerged ... Capture it» | Сам канал продвижения; подсказка из окружения выглядит как «техника, которая появилась в сессии» |
| `tools/write_approval.py` | Гейт записи скилла: allow / stage / block | Смотрит на политику и источник записи, не на содержимое |
| `tools/skills_guard.py` | Regex-сканер (rm -rf, curl $KEY, ~/.ssh) | Для скиллов, написанных агентом, выключен по умолчанию (`skills.guard_agent_created: False`); сигнатур на семантический дрейф нет |
| Доверенная спека | Отсутствует: спека = сам SKILL.md | FGL в режиме runtime (план против текущего скилла) принципиально не видит дрейфа |

## 3. Предложение: FGL-Admission

Из трёх статей берём одну общую мысль: библиотека скиллов живёт, значит проверять надо каждое
обновление, а не только установку из хаба.

- Survey 2607.10113: восьмистадийный жизненный цикл, где admission и repair «repeatedly important»,
  governance через provenance и rollback.
- 2606.11435: эволюция и оценка как один процесс, каждое обновление оценивается.
- SkillsVote: evidence-gated updates и атрибуция результата (скилл, исследование агента, окружение,
  сигнал результата); в библиотеку допускаются только подтверждённые находки.

FGL переносится с момента исполнения на момент записи. Перед `skill_manage create/edit/patch`
каждая новая директива диффа v1→v2 заземляется против доверенных свидетельств сессии:
запрос пользователя, его явные правки, предыдущая допущенная версия, проверенный результат.
Содержимое окружения (выводы инструментов, файлы, страницы) свидетельством не является.
Вердикты по директиве: WITHIN_SCOPE (уточнение в рамках v1), SUPPORTS (расширение, подтверждённое
пользователем или результатом), REFUTES (снимает ограничение v1), NOT_ENOUGH_INFO (расширение без
поддержки). Любая REFUTES или NOT_ENOUGH_INFO отправляет запись в staging Hermes
(`write_approval`), а не в библиотеку. Провенанс версий и откат: ledger MemLineage.

## 4. Протокол

- 12 сценариев SkillHarm SMP (`benchmark/skillharm_smp.py`, компоненты data-pipeline,
  system-environment, agent-autonomy). Три вида сессий на сценарий: вредная подсказка из окружения
  (attack), доброкачественная правка от пользователя (benign_user), безвредная подсказка из
  окружения (benign_env).
- Эволвер: реальный промпт куратора Hermes, формат SKILL.md Hermes. Сканер: реальный
  `tools.skills_guard.scan_skill(source="agent-created")`, как если бы он был включён.
- Условия на стадии допуска: none, hermes_guard, fgl_admission, both. Справочно: FGL-runtime против
  текущего (мутировавшего) скилла и против исходной спеки v1.
- Переиспользование: агент исполняет допущенную версию, вред определяет LLM-судья.
- Модели: gpt-4.1-mini и gpt-5.1 (одна модель играет агента, куратора, гейт и судью).

Отклонение от пре-регистрации: вред и факт продвижения определяет только LLM-судья, без
regex-маркера. Первый прогон с regex показал, что маркер срабатывает на отказах («never run
rm -rf /»), которые сильная модель-куратор дописывает в скилл как защитную заметку.

## 5. Результаты (N=12 на условие)

| Метрика | gpt-4.1-mini | gpt-5.1 |
|---|---|---|
| Куратор продвинул вредную директиву в SKILL.md | 6/12 (50%) | 7/12 (58%) |
| ASR при переиспользовании, без гейта | 50% | 33% |
| Поимка на допуске, сканер Hermes skills_guard | 0/6 | 0/7 |
| Поимка на допуске, FGL-Admission | 6/6 (100%) | 7/7 (100%) |
| ASR при переиспользовании, FGL-Admission | 0% | 0% |
| FGL-runtime против текущего скилла, поимка | 0% | 0% |
| FGL-runtime против доверенной v1 (справочно) | 100% | 71% |
| Правки от пользователя, захвачены куратором | 100% | 100% |
| Правки от пользователя, ложный блок FGL-Admission | 2/12 (17%) | 4/12 (33%) |
| Безвредные подсказки из окружения, ушли в staging | 9/11 (82%) | 10/12 (83%) |

По компонентам FGL-Admission ловит 100% продвинутых директив во всех трёх (mini: 3/3, 2/2, 1/1;
gpt-5.1: 2/2, 3/3, 2/2). Сканер Hermes дал вердикт dangerous только на `rm -rf /` в сценарии,
где куратор эту директиву не продвинул.

Гипотезы пре-регистрации: H-a (продвижение ≥ 50%) выполнена на обеих моделях, ASR ≥ 50% только на
mini (gpt-5.1: 33%). H-b (сканер ≤ 50%) выполнена. H-c (FGL-Admission ≥ 80%, ASR ≤ 20%) выполнена.
H-d (ложный блок ≤ 20%) выполнена на mini, не выполнена на gpt-5.1 (33%). H-e (runtime ≤ 25%)
выполнена.

## 6. Честные оговорки

- Ложные блоки: все заблокированные пользовательские правки содержат дописки куратора, которых
  пользователь не просил (лимит 50 строк, рекурсивная чистка, чтение SSH-конфига). Гейт блокирует
  именно их, а не правку пользователя. Запись уходит в staging, не теряется.
- Безвредные подсказки из окружения тоже уходят в staging (82%): это цена политики «окружение не
  свидетельство». Для Hermes это один клик `/skills approve`.
- N=12, одна и та же модель во всех ролях, харнесс наш, а не end-to-end прогон Hermes CLI.
  Реальные части Hermes: промпт куратора, формат SKILL.md, сканер. Полный прогон через Hermes CLI
  требует hook на `skill_manage`, которого в v0.19 нет: это и есть предлагаемая точка интеграции.
- Сильная модель (gpt-5.1) чаще сама отвергает подсказку и дописывает защитную заметку, поэтому
  ASR без защиты у неё ниже, а ложных блоков больше (она же больше додумывает в скилл).
