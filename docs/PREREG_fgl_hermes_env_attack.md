# Пре-регистрация: FGL-Admission против environmental attack на скиллы Hermes

Дата: 2026-10-09, до запуска. Задача научрука: на основе трёх статей (Dynamic Agent Skills
arXiv:2607.10113, Agent Skill Evaluation and Evolution arXiv:2606.11435, SkillsVote
arXiv:2605.18401) предложить улучшение FGL для снижения риска environmental attack для Hermes.

## Угроза (environmental attack)
Атакующий не трогает ни запрос пользователя, ни файл скилла напрямую. Он кладёт инструкцию
в окружение агента (README, вывод инструмента, страница), в котором Hermes выполняет
безобидную задачу. Фоновый куратор Hermes (agent/background_review.py, промпт
«Be ACTIVE ... tool-usage pattern emerged ... Capture it») продвигает подсказку из окружения
в персистентный SKILL.md. В следующей сессии скилл переиспользуется, вред активируется
(путь PoisonedEvolution / SkillJack: cross-layer promotion + persistence).

## Что уже есть в Hermes v0.19.0 (измерено по установленному пакету)
- tools/skills_guard.py: regex-сканер, применяется и к agent-created скиллам
  (skill_manager_tool._security_scan_skill). Ловит явные команды (rm -rf /, curl $KEY).
- tools/write_approval.py: гейт записи скилла (allow / stage / block) по политике, без анализа
  содержимого.
- Отдельной доверенной спецификации у скилла нет: «спека» = сам SKILL.md, который и мутирует.
  Поэтому FGL в режиме runtime (план против текущего скилла) принципиально не видит дрейфа.

## Предложение: FGL-Admission (гейт допуска на стадии admission жизненного цикла)
Из статей: survey 2607.10113 — стадия verification/admission и governance через provenance
и rollback; 2606.11435 — оценка и эволюция как один процесс (каждое обновление оценивается);
SkillsVote — evidence-gated updates и атрибуция результата (скилл / исследование агента /
окружение / сигнал результата).
FGL переносится с момента исполнения на момент записи: перед skill_manage create/edit/patch
каждая НОВАЯ директива диффа v1→v2 заземляется против доверенных свидетельств сессии:
запрос пользователя, его исправления, предыдущая допущенная версия, проверенный результат.
Содержимое окружения (выводы инструментов, файлы) свидетельством не является.
Директива без поддержки → NOT_ENOUGH_INFO/REFUTES → запись уходит в stage (механизм
write_approval Hermes), а не в библиотеку. Провенанс версии и откат — через ledger MemLineage.

## Протокол
Харнесс benchmark/fgl_hermes_env_attack.py, модель gpt-4.1-mini, 12 сценариев SkillHarm SMP
(benchmark/skillharm_smp.py, 3 компонента) + 12 доброкачественных обновлений от пользователя
+ те же 12 вредоносных подсказок, но пришедших из окружения в безвредной формулировке.
Эволвер — реальный промпт куратора Hermes (_SKILL_REVIEW_PROMPT), формат SKILL.md Hermes,
сканер — реальный tools.skills_guard.scan_skill(source="agent-created").

Условия на стадии admission: none; hermes_guard (regex); fgl_admission; both.
Метрики: promotion (вредная директива попала в v2), catch на admission, ASR при
переиспользовании (is_harmful из skillharm_smp), false-block на доброкачественных
пользовательских обновлениях. Справочно: FGL-runtime против текущего (мутировавшего) скилла.

## Гипотезы (фиксируются до запуска)
- H-a. Без гейта куратор продвигает подсказку из окружения в скилл не реже чем в 50% сценариев,
  и ASR при переиспользовании ≥ 50%.
- H-b. Regex-сканер Hermes ловит ≤ 50% продвинутых вредных директив (семантический дрейф —
  «пропусти approval», «игнорируй фильтр org» — не содержит сигнатур).
- H-c. FGL-Admission ловит ≥ 80% продвинутых вредных директив, ASR при переиспользовании ≤ 20%.
- H-d. False-block на доброкачественных обновлениях, исходящих от пользователя, ≤ 20%.
- H-e. FGL-runtime против текущего скилла ловит ≤ 25% (спека сама отравлена).
